# Repo cleanup plan

Survey taken 2026-09-23 on branch `capture-rate-fix`. 135 tracked files, 23 MB tracked,
33 MB of git history. This file is internal, like `roadmap.md`.

## 1. The core problem: two plotting systems, neither inside `src`

| System | Style module | Outputs | Tracked? |
| --- | --- | --- | --- |
| `results/plotting_notebook.ipynb`, 28 cells, 1.5 MB of embedded output | `results/soft_style.py`, 615 lines | `results/plots/**`, 48 PNGs | yes, 6.9 MB |
| `plotting/` package, 7 modules | `plotting/style.py`, 80 lines | `figures/**`, 14 files | no |

Nothing in `src/` imports either one, and the two style modules are unrelated. Every
figure in the paper will be regenerated, so this is the moment to collapse them into one
package inside `src` with a single entry point.

- No `tests/` anywhere. At minimum: the baseload frontier has slope exactly -1, the PAP
  first-order condition holds at an interior optimum, and the capture rates the scenario
  generator produces match the empirical ones. Those three would have caught the
  capture-rate bug.
- `paper` is a git submodule pointing at Overleaf
  (`git.overleaf.com/69c3d8989e083fa75cfa93fd`) and its checkout is currently deleted,
  showing as `D paper`. Decide: restore the submodule, or drop it and keep the manuscript
  only in Overleaf. Publishing a submodule URL exposes the Overleaf project id.

2. Delete on disk: `Code/`, `dockerfiles/`, `envs/`, `_debug_runs.txt`, `.superpowers/`,

5. Port the notebook's figure code, then delete the notebook.

commit with the pipeline run end to end afterwards.
